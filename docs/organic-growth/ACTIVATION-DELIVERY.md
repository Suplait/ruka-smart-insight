## UI critique / corrections

| Before | After | Why |
| --- | --- | --- |
| Only a guided, editable fictional example | Real CSV mode first; guided example still available | Deliver an actual usable outcome without losing explanation |
| File replacement could leave misleading prior context | New file/error/mapping changes invalidate computed results | A stale result must never look like analysis of a newly selected file |
| Built-in samples could be mixed with one uploaded file | Clear warning and disabled comparison until all files are replaced or sample reset | Prevent a real purchase from being compared to fictional documents unnoticed |
| Dense mobile mapping controls | 16px mobile selects, compact loaded-file states, 44px targets | Avoid iOS focus zoom and excessive scrolling while retaining explicit mapping |
| Result alone could be mistaken for payment approval | Reasons, input values, source rows, limitations and export | Make the result auditable and keep the decision with the user |
| Chipax/Toteat links implied broader features than the destination guides prove | Labels specify XML intake and reviewed purchase posting | Users should know what the destination actually explains |

This table records inspected corrections, not a claim that a skill guarantees quality. Final production/browser gates remain required.
